## New in 1.2.0

- **3D files are recognised automatically.** Lumen finds out whether a file is 3D and how the eyes are
  arranged: from what the file says about itself, from the name (`3D`, `SBS`, `H-SBS`, `TAB`, `HOU` …), and by
  comparing the picture halves of a few frames. Half or full resolution follows from the frame size. On a 3D
  output profile the check runs before the file starts, so playback begins in the right format; on a 2D
  profile a 3D file is shown as one eye. *Picture → 3D source* shows what was found and why, and still lets
  you choose by hand.
- **MKV with two views (MVC).** Files made from a Blu-ray 3D that carry both views in one H.264 stream play
  in 3D with both views, on every platform, like the disc itself.
- **Scaling and decoding follow the hardware.** New profiles and the *Desktop* preset use scaling quality
  *Automatic*: *fast* on a software renderer, *balanced* on integrated graphics, *high* on a graphics card
  or Apple Silicon. Hardware decoding *Automatic* hands pictures to the renderer directly, copies them when
  a filter computes on the CPU (3D conversion), and stays off where no hardware decoder exists (MVC).
- **Playback adapts when frames are lost.** If the machine cannot keep up, Lumen steps down the scaling,
  then relieves the software decoder (skips the deblocking filter, finally leaves out frames so the sound
  stays in sync), and shows in the control window what it took back. What a profile could not manage for a
  kind of material is remembered for two weeks. Can be switched off per profile.
- **No dropped frames at the start, and none while playing.** A file, a DCP or a disc now starts when its
  first picture is on screen instead of dropping the first pictures while the sound already runs. On an Apple M3 Pro, H.264, HEVC
  (10 bit), AV1 and VP9 in 4K at 60 pictures per second, HEVC in 8K, ProRes, interlaced MPEG-2, MVC with both
  views and JPEG 2000 in 2K and 4K played for the length of the test clips without a single dropped frame.
- **JPEG 2000 (DCP) decodes 20 to 28 % faster.** Lumen's FFmpeg runs the inverse wavelet transform over
  neighbouring memory and inlines the arithmetic decoder; the pictures are the same bit for bit. A 4K DCP at
  24 pictures per second now plays at full resolution on an M3 Pro (27 pictures per second at 271 Mbit/s,
  before about 22).
- **The embedded player window draws in its own thread** (macOS, and wherever a profile embeds the picture).
  The picture no longer waits for the control window, and frame-sequential 3D reaches the display's rate:
  120 pictures per second on a 120 Hz screen, where it drew 65 to 90 before. That mode also uses the fast
  scaler now, because every picture has only a few milliseconds.
- **Fixed: playback stayed at 0:00 with bitstream sound** when the audio device does not take the bitstream
  (a Mac's speakers, most headphones). mpv fell back to decoding but never started the sound; 1.1.0 and
  stock mpv 0.41 do the same. This hit the supplied preset *1080p DLP 3D projector* on a machine without
  a receiver.
- **New logo:** an eye with a disc for an iris.
- **Automatic deinterlacing** for DVDs and 1080i material; the switch in the *Picture* tab now forces it.
- **Fixed: crash when opening a Blu-ray.** The disc overview, the disc navigation and the player could open
  discs at the same moment; libbluray then freed the same memory twice.
- **Fixed:** a message about a missing Vulkan library was shown as a playback error on macOS.
- Lumen's own window falls back to mpv's older renderer if the new one cannot start.
- All new texts are translated into the 16 interface languages.

## Notes

- **The frame counts above come from one Apple M3 Pro** and from clips of 12 to 40 seconds made from one source
  (upscaled to 4K and 8K), in the embedded player window. JPEG 2000 at 48 pictures per second (3D DCP, 2K)
  played without a dropped frame at 249 and at 281 Mbit/s; the decoder alone reaches 73 and 64 pictures per
  second there. At 403 Mbit/s, more than a DCP may carry, it reached 46.
- **Other machines were not measured as players.** The CI machines (virtual, 3 or 4 cores, no graphics card;
  Windows, macOS and Linux on x86-64 and ARM64) now print how fast the software decoder alone runs on
  generated clips (`tools/bench_decode.sh`, in the log of the Blu-ray 3D test). That is a lower bound for
  small machines, not a statement about any real one.
- **Frame-sequential 3D at 120 Hz is not free of lost pictures.** On the Mac's own 120 Hz panel the window is
  drawn 118 to 120 times a second; mpv still counted a late picture every 2 to 5 seconds, and with an MVC
  source it left out about one picture in two seconds to catch up. Every such picture swaps the eyes for
  shutter glasses. No 120 Hz projector was available, so how this behaves on a real 3D display is not known.
- **Blu-ray 3D through the disc navigation** starts without dropped frames now, but lost 0 to 8 pictures in
  40 seconds on the test image (36 Mbit/s). The MVC decoder works on one core (63 picture pairs per second
  on the M3 Pro); an MVC file at a lower bit rate lost none.
- **Tested on one machine with a handful of files.** The 3D detection was run against one half side-by-side
  clip, one MVC MKV and one Blu-ray 3D image on an Apple Silicon Mac, and in CI against generated clips (two
  shifted views side by side and on top of each other) and 2D pictures that must not pass (colour bars, test
  cards, letterboxed and fractal pictures). No real top-and-bottom film, no file with 3D metadata in the
  container and no 3D display were available.
- **Which eye comes first is not detected.** Left is assumed unless the file name says `RL`. Anaglyph and
  checkerboard files are not recognised.
- A 3D file on a 2D profile switches to one eye about a second after it starts, because there the check runs
  after loading.
- **The hardware classes come from the driver's name.** Windows and Linux machines, integrated graphics and
  software renderers were not tried on real hardware; only the classification of their driver names and the
  rules that follow from it are tested. The runtime adaptation was provoked with an 8K 60 fps file on the
  same Mac; its rules are tested with simulated counters.
- The fallback to mpv's older renderer could not be tried: none of the test machines fails to start the new one.
- Skipping the deblocking filter shows as blocks in low-bitrate video. It only happens when frames are being
  lost; *Adapt performance automatically* in the profile switches it off.
- Subtitles of a 3D **file** are drawn once over the whole picture, not once per eye; per-eye subtitles
  with depth exist for Blu-ray 3D discs only.
- The notes of 1.1.0 about casting, frame-sequential 3D, the TV apps, code signing and untested hardware
  still apply.
