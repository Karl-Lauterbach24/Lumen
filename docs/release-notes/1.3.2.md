## New in 1.3.2

Found with a pressed Blu-ray 3D that has a classic (HDMV) menu – the first such disc Lumen was tried with.

- **Fixed: the start of a disc stalled, and what came before the menu was skipped.** A disc start runs
  through several playlists – warning, studio logo, menu – and every playlist counts its time from the same
  start. At each change the time jumped back, the player held the picture and threw away everything "in the
  past": on the test disc about ten seconds of standstill, 596 dropped pictures, both logos gone and the
  first seconds of the menu. Lumen now lets each playlist continue where the last picture of the previous one
  ended. The same disc: 0 dropped pictures, warning, logo and menu follow each other without a gap. This
  also covers menus that loop.
- **Fixed: no sound after *Play Movie*.** The menu's sound was AC-3, the film's DTS-HD – on the same stream
  number (PID). The demuxer keeps the format it first saw for a PID, so the film's sound went to the AC-3
  decoder: a thousand decoding errors and silence. A stream whose format changes with the playlist now gets
  a number of its own; the player sees a new track and Lumen switches to it. Going back to the menu and into
  the film again works the same way, without the playback reset that a leftover packet used to cause.
- **Classic (HDMV) menus tried on a real disc.** 1.3.0 drew them for the first time but had only been tried
  with subtitles. On the test disc the three-level menu (*Play Movie · Languages · Scene Selections*, then
  *Spoken Languages · Subtitles*, then the list of languages) is drawn for both eyes, arrow keys and Enter
  work, and the language picked in the disc's menu is the one the film plays.
- **Track lists of a disc.** *Audio* and *Subtitles* show the streams of the playlist that is playing – not
  those of the menu before it –, in the disc's order and with their languages (`ENG · DTS-HD MA · 5.1`
  instead of six times `AC-3`). The languages come from the playlist; the data stream itself has none.
- **Blu-ray 3D:** when a key ends a playlist (Enter in the menu), its last, cut-off picture is no longer
  handed to the decoder (one damaged picture at the change). A playlist that starts again – a menu loop –
  reads its second view from the beginning.

## From 1.3.1

- **Disc menus written in Java (BD-J) start on macOS and Windows.** The packages contain libbluray's Java
  archive for the libbluray they are built with (1.5.0). What remains to be installed is a **Java runtime**
  (JRE or JDK from version 8 on, for the same processor type as Lumen). Without one the main feature plays
  and the *Titles* page says why.
- **Lumen finds the Java runtime** where libbluray does not: macOS through `/usr/libexec/java_home` and
  Homebrew's `openjdk`; Windows in the usual folders under `Program Files` when the installers' registry
  entries are missing, a folder `jre` next to `lumen.exe` first. A `JAVA_HOME` that is set stays as it is.
- **Linux:** the packages name the distribution's `libbluray-bdj` (recommended in the `.deb`, suggested in
  the `.rpm`).
- A folder `bdj` in Lumen's data folder is only used when it holds the archive of the libbluray in use.

## For developers

- `TsRemap` gives a stream its own PID when its format differs from what the demuxer knows under that PID –
  in the packets and in the programme table, whose checksum is recalculated on the fly. `tsremap_test` checks
  it with a table that spans two packets; it runs in `tools/test_bd3d.sh` on every CI platform.
- `scanM2ts` reads the first and the highest picture time stamp of a block; `BlurayNav` uses it to join
  playlists on one time line.
- `resources/bdj/`, `tools/build_bdj.sh`, `tools/test_bdj.sh` (a generated disc with a Java menu, run through
  libbluray), see [`resources/bdj/README.md`](https://github.com/Karl-Lauterbach24/Lumen/blob/main/resources/bdj/README.md).
- The Windows package builds now build and run the playlist time line check from 1.3.0, the new `TsRemap`
  test and the BD-J test. They only built `lumen` and `mvcmerge_test`, so on Windows the time line check was
  skipped – the 1.3.0 notes said it ran on every CI platform, which was true for Linux and macOS only.
- `LUMEN_BD_DUMP=out.m2ts` records the stream a Blu-ray hands to mpv. `LUMEN_PLAYER_SNAPSHOT=shot.png@+8,+20`
  saves the player window at several moments after the start, without pausing.

## Checked, and known limits

- Checked on macOS with one pressed Blu-ray 3D (HDMV menu, decrypted through the store plugin *My AACS
  Plugin*): disc start, menu and its sub-menus with keys, *Play Movie*, back to the menu and into the film
  again, a language chosen in the disc's menu, main feature with seeking. The stream handed to the player was
  recorded and decoded again: picture time stamps run through all playlist changes without a jump, no decoder
  errors.
- **BD-J menus were not checked with a pressed disc.** The generated disc with its Java menu runs with the
  shipped archive on macOS (Apple Silicon and Intel, Java 8, 17 and 21) and Windows (x64 with Java 17, ARM64
  with Java 21), in the player window on macOS. Real BD-J menus are large programs; libbluray runs many of
  them, not all. A menu that does not come up can be left with *Main feature* on the *Titles* page, or
  skipped with `--main` or by switching off *Start with disc menu*.
- A 2D disc with a classic menu was not at hand. It takes the same path except for the mixing of the second
  view; at a playlist change forced by a key it can show one damaged picture.
- Seeking in a film played from a disc: the player still resets playback a second time right after the jump
  (a cut-off sound packet of the old position). As before; the jump takes a moment longer than it should.
- The search for Java in the folders under `Program Files` was not tried on a Windows computer.
