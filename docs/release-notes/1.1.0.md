## New in 1.1.0

- **Casting.** The new cast button sends the player's picture and sound to a TV or receiver on the same
  network: DLNA/UPnP renderers, Chromecast, AirPlay, the new Lumen TV apps, or any browser. Lumen encodes what
  the player window would show, disc menus and subtitles included, as 1080p or 720p H.264 with stereo sound.
  You keep controlling playback in Lumen.
- **Lumen TV.** Receiver apps for Android TV, Samsung (Tizen) and LG (webOS) in a repository of their own:
  [Lumen-TV](https://github.com/Karl-Lauterbach24/Lumen-TV). The TV remote operates Lumen (disc menus, pause,
  seeking). Any other device can open the address shown in the Cast dialog in its browser.
- **Miracast and AirPlay mirroring** through the operating system: a button in the Cast dialog opens the
  system's wireless-display setting; the receiver then is a normal screen for Lumen.
- **Blu-ray 3D on every platform.** All packages now contain FFmpeg-mvc; before, only Windows x64 did.
- **The same media libraries everywhere.** x264, FFmpeg-mvc and mpv are built from the same pinned sources
  for all eight packages. The Linux packages bring them along instead of using the distribution's mpv and
  FFmpeg, so Debian and Fedora now behave like Windows and macOS, including DVD seeking (libdvdnav 7).
- **Fixed: black picture with the default chroma scaler.** mpv left part of a scaler's weight table
  uninitialised; depending on what the memory held before, the colour planes became invalid and the picture
  stayed black for the whole playback. Lumen's mpv build now zeroes the table
  ([`tools/patches`](https://github.com/Karl-Lauterbach24/Lumen/tree/main/tools/patches)). It was found in the
  cast test; the player window is drawn by the same code.
- **Frame-sequential 3D for shutter glasses (experimental).** A new 3D output format shows one eye per
  display refresh with a free pattern, optional sync pictures (an attempt at DLP-Link on fast TVs), black
  pictures, and a trigger box for light-sensor emitters. All of it is adjustable in the output profile.
- All new texts are translated into the 16 interface languages.

## Notes

- **Casting was not tested with real devices.** The stream, device discovery and the DLNA, Chromecast, AirPlay
  and Lumen TV protocols are tested automatically against stand-ins, and the stream was played in a desktop
  browser. No real TV, Chromecast, AirPlay or DLNA device was available.
- **AirPlay** works only with receivers that accept video without pairing. Most current Apple TVs and
  AirPlay 2 televisions refuse; Lumen says so. Use the system's screen mirroring for those.
- The cast stream is SDR and stereo, 3D is cast in 2D, and over HLS the picture arrives three to four seconds
  late. The computer decodes and encodes in real time.
- Lumen opens network port 47800 only while the Cast dialog is open or a cast is running, unless you switch
  on *Stay reachable for Lumen TV apps*. Windows asks once whether to allow it through the firewall.
- **Frame-sequential 3D was not tested with any glasses or a 120 Hz display**, only the generated picture
  sequences. Whether DLP-Link glasses lock onto sync pictures on a TV depends on the model and may not work
  at all. A single dropped frame swaps the eyes.
- **The Lumen TV apps were not run on a real television.** The Android app is compiled in CI; the Samsung
  package has to be signed with your own Samsung certificate.
- Tested automatically for every package: build, the Blu-ray 3D decoder, package installation, start of the
  control window and a self-test of the packaged libraries. The cast test runs on Linux and macOS, where the
  CI machines have no graphics card: there it checks the stream and the receivers, but not frame rate and
  regularity. Those, and audio/video sync to about 30 ms, were measured on a Windows machine with a graphics
  card. Casting from a real Mac or Linux PC has not been tried.
- Still not tested: playback on real hardware for Windows ARM64, Intel Macs and Linux, and physical discs in
  a drive.
- The translations other than English and German were made with machine assistance and have not been reviewed
  by native speakers.
- Lumen contains **no** copy-protection circumvention. AACS, BD+ and CSS work only with libraries you add
  yourself through a plugin.
- The Windows packages are not code-signed (SmartScreen: "More info" → "Run anyway"). The macOS apps are
  signed ad hoc, not notarized: right-click `Lumen.app` → **Open**, or run
  `xattr -dr com.apple.quarantine /Applications/Lumen.app`.
